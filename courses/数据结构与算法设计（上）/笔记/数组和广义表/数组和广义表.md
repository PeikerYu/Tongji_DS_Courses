## 多维数组
```cpp
#define MAX_ARRAY_DIM 8 //定义最大维数
struct Array
{
    int *base;
    int dim;
    int *bound; //bounds 是一个长度为 dim 的整型数组，用来存每一维的长度
    int *constants; //地址计算用的乘数（把多维下标变成一维偏移）
};
```

---

## 1）先说本质：为什么需要 constants？

多维数组在内存里其实是 **一长条连续空间**：

比如二维 `a[3][4]`，内存里就是 12 个元素排成一排：

```
a[0][0] a[0][1] a[0][2] a[0][3] a[1][0] ... a[2][3]
```

所以访问 `a[i][j]` 时，关键就是算出它在这一长条里的位置（偏移量 off）。

### constants 就是用来把多维下标快速换算成 off 的

[
off = i_0 \cdot constants[0] + i_1 \cdot constants[1] + \dots + i_{dim-1}\cdot constants[dim-1]
]

---

## 2）constants 到底存的是什么？

在 **行主序（C 语言）** 下：

* 最后一维变化最快，所以它每加 1，偏移量就加 1
  👉 `constants[dim-1] = 1`

* 倒数第二维每加 1，要跨过“最后一维的一整行/一整段”
  👉 `constants[dim-2] = bounds[dim-1]`

* 再往前一维每加 1，要跨过“后面所有维度组成的一个大块”
  👉 `constants[k] = bounds[k+1] * constants[k+1]`

**一句话：**

> `constants[k]` = 第 k 维下标增加 1 时，在线性存储中要跳过多少个元素。

---

## 3）举例 1：二维数组 a[3][4]

### 已知

* `dim = 2`
* `bounds[0] = 3`（3 行）
* `bounds[1] = 4`（4 列）

### 求 constants

* `constants[1] = 1`（最后一维）
* `constants[0] = bounds[1] * constants[1] = 4 * 1 = 4`

所以：

* `constants = [4, 1]`

### 解释一下这个 [4,1]

* 行号 i 每加 1，要跳过 4 个元素（整整一行）
* 列号 j 每加 1，只跳过 1 个元素（往右一个格）

### 算 off（比如 a[2][3]）

[
off = 2\cdot 4 + 3\cdot 1 = 8 + 3 = 11
]

意思是：`a[2][3]` 是线性数组里的第 11 号（0-based）元素，也就是第 12 个元素。

---

## 4）举例 2：三维数组 a[2][3][4]（这个更能看出 constants 的意义）

### 已知

* `dim = 3`
* `bounds = [2, 3, 4]`

  * 第 0 维：2 块
  * 第 1 维：每块 3 行
  * 第 2 维：每行 4 列

### 求 constants（从后往前）

* `constants[2] = 1`
* `constants[1] = bounds[2] * constants[2] = 4 * 1 = 4`
* `constants[0] = bounds[1] * constants[1] = 3 * 4 = 12`

所以：

* `constants = [12, 4, 1]`

### 解释这个 [12,4,1]

* 第 2 维（最里面那维）+1 → off +1（挪 1 个元素）
* 第 1 维 +1 → off +4（跨过一整行 4 个元素）
* 第 0 维 +1 → off +12（跨过一个 3×4 的大块，共 12 个元素）

### 算 off（比如 a[1][2][3]）

[
off = 1\cdot 12 + 2\cdot 4 + 3\cdot 1
= 12 + 8 + 3
= 23
]

说明 `a[1][2][3]` 在拉平成一维后的下标是 23（0-based）。

---

## 5）你最容易记住的“口诀”

**行主序（C）：**

* 最后一维常量 = 1
* 前一维常量 = 后一维长度 × 后一维常量
* constants 表示“每一维走一步要跳过多少个元素”

## 三元组
```cpp
//三元组：用来存放稀疏矩阵中的非零元
#define MAXSIZE 10000 //非零元最大个数值
struct Triple
{
    int i,j; //行下标和列下标
    int e; //该位置的值
};
struct TSMatrix
{
    Triple data[MAXSIZE+1]; //存非零元
    int mu,nu,tu; //行数、列数、非零元个数
};

//稀疏矩阵的转置
void Transpose(TSMatrix M,TSMatrix &T)
{
    T.mu=M.nu;
    T.nu=M.mu;
    T.tu=M.tu;
    int q;
    if(T.tu!=0)
    {
        for(int col=1;col<=T.mu;col++)
        {
            for(int p=1;p<=M.tu;p++)
            {
                if(M.data[p].j==col)
                {
                    T.data[q].i=M.data[p].j;
                    T.data[q].j=M.data[p].i;
                    T.data[q].e=M.data[p].e;
                    q++;
                }
            }
        }
    }
}

//快速转置 1-based
void FastTranspose(TSMatrix M,TSMatrix &T)
{
    int *num=(int*)malloc(sizeof(int)*(M.nu+1)); //辅助数组：num[col]表示矩阵第col列中非零元的个数
    int *cpot=(int*)malloc(sizeof(int)*(M.nu+1)); //辅助数组：cpot[col]表示第col列的第一个非零元素在T.data中的恰当位置
    T.mu=M.nu;
    T.nu=M.mu;
    T.tu=M.tu;
    if(T.tu!=0)
    {
        for(int col=1;col<=M.nu;col++)
        {
            num[col]=0;
        }
        for(int t=1;t<=M.tu;t++)
        {
            num[M.data[t].j]++;
        }
        //以上是建立Num数组
        cpot[1]=1;
        for(int col=2;col<=M.nu;col++)
        {
            cpot[col]=cpot[col-1]+num[col-1];
        }
        //以上是建立cpot数组 cpot是动态变化的
        for(int p=1;p<=M.tu;p++)
        {
            int col=M.data[p].j;
            int q=cpot[col];
            T.data[q].i=M.data[p].j;
            T.data[q].j=M.data[p].i;
            T.data[q].e=M.data[p].e;
            ++cpot[col];
        }
    }
}
```
你卡住的点非常典型：`++cpot[col];` 其实就是**“写指针后移一格”**，用来保证**同一列（转置后同一行）的多个非零元不会写到同一个位置**。

我用你这段代码的语境（1-based，下标从 1 开始）解释。

---

## 先回忆：cpot[col] 是什么？

你自己注释写得很准：

> `cpot[col]` 表示 **原矩阵第 col 列**的第一个非零元在 **T.data** 里应该放的起始位置。

更准确一句话：

* 原矩阵 M 的第 `col` 列
  经过转置会变成 T 的第 `col` 行
* `cpot[col]` 就是：**T.data 中“这一行”的下一个空位下标**

也就是说，`cpot[col]` 不是只存“第一个位置”，它在运行过程中会被当成**动态游标/写指针**用。

---

## 最后一段在干嘛？（关键逻辑）

```c
int col = M.data[p].j;   // 这个非零元来自 M 的第 col 列
int q = cpot[col];       // q 是它在 T.data 里该放的位置
T.data[q] = (j, i, e);   // 写进去
++cpot[col];             // ⭐ 写完后，该列的“下一个空位”往后挪一格
```

### 为什么必须 `++cpot[col]`？

因为同一列里可能有**多个非零元**。

如果你不加这句，那么同一列的所有元素都会：

* `q = cpot[col]` 得到同一个 q
* 一直写 `T.data[q]`
* 结果后写的把先写的覆盖掉，最后只剩一个

所以 `++cpot[col]` 的作用就是：

> **下次再遇到同一列的元素时，让它写到下一格，而不是覆盖上一格。**

---

## 用一个超小例子直接秒懂

假设原矩阵 M 的第 2 列有 3 个非零元，转置后它们都要进入 T 的第 2 行。

你算出来：

* `cpot[2] = 5`（意思：第2行从 T.data[5] 开始放）

接下来扫描 `p=1..tu` 时，遇到三次 `col=2`：

### 第一次遇到 col=2

* `q = cpot[2] = 5`
* 写到 `T.data[5]`
* `++cpot[2]` → `cpot[2]=6`

### 第二次遇到 col=2

* `q = cpot[2] = 6`
* 写到 `T.data[6]`
* `++cpot[2]` → `cpot[2]=7`

### 第三次遇到 col=2

* `q = cpot[2] = 7`
* 写到 `T.data[7]`
* `++cpot[2]` → `cpot[2]=8`

结果：第2行的 3 个元素就顺序放到了 5、6、7 三个位置。

---

## 你可以把它记成一句口诀（考试超好用）

> `cpot[col]` 一开始是“起始位置”，运行时变成“写指针”；
> `++cpot[col]` 就是“写完一个，该行指针后移”。

---

## 小提醒：你这份代码还有个下标坑（不影响你理解，但考试容易错）

你 `malloc(sizeof(int)*M.nu)` 但却用 `col=1..M.nu` 访问 `num[col]`，这会越界（因为 C 数组下标从 0，长度是 M.nu 的话最大是 M.nu-1）。

如果你坚持用 1-based，应该分配 `M.nu+1`：

```c
int *num  = (int*)malloc(sizeof(int) * (M.nu + 1));
int *cpot = (int*)malloc(sizeof(int) * (M.nu + 1));
```

否则就改成 0-based 全部从 0 开始。
